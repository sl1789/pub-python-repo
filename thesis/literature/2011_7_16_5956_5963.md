# Zhou, Lei, Ye (2011) — *Large-Scale Data Sets Clustering Based on MapReduce and Hadoop*

- **PDF:** `2011_7_16_5956_5963.pdf`
- **Venue:** *Journal of Computational Information Systems*, Vol. 7, No. 16, pp. 5956–5963.

> **Relevance note:** This paper has **no direct connection to option
> pricing or Monte Carlo simulation.** It is a systems / data-mining
> paper about parallelising the K-Means algorithm on Hadoop. It is
> useful for the thesis as a reference on the MapReduce programming
> model and the typical performance / scalability arguments that motivate
> Apache Spark.

## Methodology (no Monte Carlo)
**Parallel K-Means clustering on MapReduce / HDFS.** Documents the map
step (assign each point to its nearest centroid) and the reduce step
(recompute centroid coordinates from points sharing the same label) and
chains successive MapReduce jobs until centroid convergence.

## Type of data
Reports experiments on **document clustering** (large-scale text
collections). Data is empirical but unrelated to finance.

## Computational setup
**Hadoop cluster** with HDFS for distributed storage. Number of nodes
and node specifications are described qualitatively rather than as a
formal benchmark.

## Key contribution
Provides a clear, didactic walk-through of:

- the MapReduce programming model (mapper / combiner / reducer signatures,
  key/value typing rules),
- the Hadoop infrastructure (JobTracker / TaskTracker, HDFS replication,
  fault tolerance),
- a worked example of how an iterative algorithm (K-Means) maps onto a
  *chain* of MapReduce jobs.

## Strengths
- Useful as a primer on MapReduce semantics.
- Demonstrates the standard idiom for converting an iterative algorithm
  into a sequence of MapReduce passes.
- Empirically confirms near-linear speed-up on document clustering up
  to the experimental cluster size.

## Limitations
- No financial / Monte Carlo content.
- Hadoop-specific: many of the limitations identified (per-iteration
  disk shuffle, lack of in-memory caching) are precisely what later
  drove the development of Apache Spark.
- Experimental setup is briefly described; replication is non-trivial
  from the paper alone.
- Compares only against single-machine K-Means; no comparison to other
  parallel frameworks (MPI, Spark, etc.).

# Zhang, Gong, Peng, Liu (2011) — *Parallel Option Pricing with BSDEs Method on MapReduce*

- **PDF:** `05764022.pdf`
- **Venue:** IEEE International Conference (2011), Shandong University.

## Methodology (Monte Carlo variant used)
Backward Stochastic Differential Equations (BSDEs) framework of El Karoui,
Peng and Quenez (1997) for option pricing, solved numerically with the
fully discrete $\theta$-scheme on a time-space grid. Each grid update
requires a conditional expectation that is estimated by **plain (i.i.d.)
Monte Carlo simulation of Brownian increments** at every node of every
time layer. The pricing is therefore a *backward iteration in time* where
each step is itself an embarrassingly parallel Monte Carlo problem over
the spatial grid.

## Type of data
Purely **synthetic**. The paper does not benchmark against real option
quotes; it demonstrates the method on standard European call payoffs
$\max(S_T - K, 0)$ with parameters chosen for illustration.

## Computational setup
**Hadoop MapReduce** cluster (open-source Apache Hadoop on commodity
hardware). For each backward time step, a Map task is launched per
spatial grid point and a Reduce task aggregates the Monte Carlo expected
values per key. Successive time layers are chained by re-injecting the
reducer output as mapper input. No GPU / no Spark — pre-Spark era.

## Key contribution
First (or among the first) papers to **port BSDE-based option pricing to
MapReduce**. Provides the explicit Map and Reduce function bodies that
encode the $\theta$-scheme update plus its embedded Monte Carlo step, and
sketches the chained-job architecture.

## Strengths
- Embeds Monte Carlo inside the conditional-expectation step of BSDEs, so
  it inherits the full generality of the BSDE framework (incomplete
  markets, non-linear payoffs, hedging diagnostics).
- Concrete pseudocode for the Map and Reduce primitives, easy to map
  one-to-one onto a Hadoop job.
- Argues for near-linear speed-up on commodity clusters as a substitute
  for hand-rolled HPC code.

## Limitations
- No empirical validation against market prices; experiments are
  synthetic and only report runtime / speed-up.
- The Map/Reduce iteration introduces per-step disk shuffle that
  dominates I/O for fine grids — characteristic of Hadoop and one of the
  motivations that later led to Spark / in-memory engines.
- Limited to European exercise; American-style or path-dependent
  derivatives would require non-trivial extensions (Longstaff–Schwartz).
- Choice of grid resolution and the $\theta$-scheme parameters is not
  systematically studied.
